# Ресурс

Прототип сервиса обмена ресурсами и потребностями. Человек **что-то даёт** и
**что-то получает** — но «даю» и «прошу» это **два независимых акта**, а не бартер
«стол за помидор». Баланс «даю/прошу» — мягкий индикатор, а не блокировка сделки.

## Архитектура

Один бэкенд и одна база данных обслуживают **два клиента из общего кода**:

- **Сайт** — открывается без VPN, вход по логину/паролю (JWT).
- **Telegram Mini App** — внутри Telegram (в РФ через VPN), вход по `initData`.

Механизм везде одинаковый, отличаются только инструменты входа — это вынесено в
адаптер авторизации (`frontend/src/web` vs `frontend/src/miniapp`). Бизнес-логика
живёт только в бэкенде.

```
frontend/
  src/core/      общий код (UI + API-клиент)
  src/web/       адаптер: логин/пароль        → web.html
  src/miniapp/   адаптер: Telegram initData   → miniapp.html
backend/
  app/matching.py   зеркальный мэтчинг
  app/contract.py   Человеческий договор
  app/ai.py         ИИ-уточнения формы
  app/api/          REST-эндпоинты
```

Стек: FastAPI + SQLAlchemy + PostgreSQL, Vue 3 + Vite, Docker Compose.
Слой авторизации (пароль / Telegram / VK / Supabase) — точка расширения; схема БД
ложится на Supabase Postgres + RLS.

## Что реализовано в первом билде

Это три приоритета из брифа — ядро ценности «Ресурса»:

1. **Форма «Даю/Прошу»** — 4 категории (Время·Навык·Услуга / Вещь·Товар /
   Пространство·Место / Знание·Опыт), у каждой свои поля. ИИ задаёт до 5 уточняющих
   вопросов с короткими вариантами ответов; ресурсодателю дополнительно — «кому
   идеально подойдёт».
2. **Зеркальный мэтчинг** — жёсткий фильтр (категория, гео, сроки, условия) →
   балл соответствия 0–100 по весам параметров (важные ×4) → коррекция репутацией
   дающего → порог мэтча 40% (поднимаемый).
3. **Человеческий договор в чате** — в чате сделки есть боты («Ресурс» + медиатор);
   по ходу диалога в реальном времени собирается договор (суть, обмен ценностями,
   критерии качества, план Б, декларация). Один акт = один договор; правка поля
   сбрасывает подписи (живой документ). После завершения — отзыв по STAR, который
   пересчитывает капитал доверия.

## Структура данных (перенос «Подари» → «Ресурс»)

| «Подари»       | «Ресурс»             |
|----------------|----------------------|
| `gifts`        | `resources`          |
| `wishes`       | `needs`              |
| `transactions` | `acts` + `contracts` |
| `reviews`      | `reviews` (STAR)     |
| `profiles`     | `profiles` (+ капитал доверия, уровень, баланс даю/прошу) |
| —              | `matches` (новый)    |

## Запуск

```bash
cp .env.example .env
docker compose up --build
```

- Сайт: http://localhost:5173/web.html
- Mini App: http://localhost:5173/miniapp.html (рабочая авторизация — только внутри Telegram)
- API: http://localhost:8000 (доки: http://localhost:8000/docs)

### Локально без Docker

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload     # БД по умолчанию — SQLite

pytest                            # тесты движка и API
```

## Дальнейшие итерации (из брифа, вне первого билда)

- Слой 0 «Подари» (баллы/XP, рефералы, ИИ-по-фото, онбординг, хранилище) —
  переносится из исходного репозитория «Подари».
- Слой 2: база знаний (STAR-кейсы), комиссия по спорам, вариации обмена, показ экономии.
- Надстройка: КТУ / блокчейн вклада (пока — журнал фиксаций), тарифы/подписки,
  ИИ-агрегация опыта.
